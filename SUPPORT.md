# Getting help with bdd2pw

The right channel depends on what you need.

## Something's broken

Open a **bug report** issue: https://github.com/javvadivijayprasad/bdd2pw/issues/new?template=bug_report.yml

Include the `.feature`, the command you ran, bdd2pw's `BDD_REVIEW.md`
output, and the bdd2pw version (`npx bdd2pw --version`). The issue
form prompts for all of these.

## I'd like a new feature

Open a **feature request** issue: https://github.com/javvadivijayprasad/bdd2pw/issues/new?template=feature_request.yml

If possible, include a real-world `.feature` file that demonstrates
the gap. "Here's the step shape I keep writing and bdd2pw doesn't
match" is the strongest motivator.

## I want to ask a question / discuss an idea

Use **GitHub Discussions**: https://github.com/javvadivijayprasad/bdd2pw/discussions

Good discussion topics:
- "Does bdd2pw support X dialect?"
- "What's the recommended way to integrate with CI tool Y?"
- "I'm thinking about contributing Z — thoughts before I start?"
- "Comparing bdd2pw vs playwright-bdd for use case W."

## I think I found a security issue

**Do not open a public issue.** See [`SECURITY.md`](./SECURITY.md)
for the private reporting flow.

## I want to contribute

Read [`CONTRIBUTING.md`](./CONTRIBUTING.md), then look at open issues
labeled [`good first issue`](https://github.com/javvadivijayprasad/bdd2pw/labels/good%20first%20issue)
or [`help wanted`](https://github.com/javvadivijayprasad/bdd2pw/labels/help%20wanted).

## Response-time expectations

bdd2pw is a solo-maintained open-source project. Response times are
best-effort:

| Channel | Target |
| --- | --- |
| Security report | 72 hours to acknowledge |
| Bug (regression on supported minor) | 7 days to triage |
| Bug (older minor) | Not actively triaged — upgrade first |
| Feature request | Looked at in weekly review |
| Discussion | Variable — community-answerable |

If you need a faster response, consider the commercial support option
above.
